# Роли сообщества CZM

Управление из игры и отметки серверов описаны в [инструкции админ-панели](ADMIN_PANEL_RU.md).

Роли выдаёт главный администратор через личный чат служебного бота. Данные о правах хранятся на сервере; подпись в нике или изменённый клиент полномочий не дают. Существующий SUPPORT сохраняется. Бот не становится инструментом обычных модераторов.

| Роль | Оформление и возможности |
| --- | --- |
| SUPPORT | Существующий золотой щит и полномочия поддержки |
| Moderator | Синий щит; модерация чата и наказания через игру |
| Official Tester CZM | Фиолетовый значок инструментов; обращения с фото и текстовым файлом |
| Server owner [Project] | Зелёный акцент и корона; до пяти серверов проекта в профиле |

Все оформления используют общий стиль карточек. Роль видна в профиле, общем чате, лобби и Топ 100; награды рейтинга сохраняются отдельно. Можно иметь несколько ролей; основной значок выбирается в порядке SUPPORT, Moderator, Tester, Server owner. Серверы проекта доступны при наличии роли владельца независимо от основного значка.

У любого аккаунта с одной из этих ролей **нет кнопки Telegram**. Обычный зарегистрированный игрок может добавить или убрать необязательный контакт через Настройки → Профиль → Сообщество. Рейтинг сам по себе не считается служебной ролью. При выдаче роли сохранённый контакт скрывается, при снятии последней роли снова доступен. Принимаются только @username и обычная ссылка https://t.me/username, без произвольных адресов и команд Telegram.

## Команды главного администратора

Команды работают только для настроенных владельцев бота в личном чате. ID — публичный ID зарегистрированного аккаунта, не почта и не секретный ключ.

```text
/role ID moderator
/role ID tester
/role ID server_owner Название проекта
/unrole ID moderator
/unrole ID tester
/unrole ID server_owner
/moderators
/moderator ID
/moderator ID 2
/mod_pause ID
/mod_resume ID
/mod_undo ID
/mod_undo ID all
```

`/role` не выдаёт SUPPORT. Новые роли не назначаются автоматически. Команда повторной выдачи server_owner обновляет название проекта.

`/moderator ID [страница]` показывает текущую серию, период, число действий, блокировок за всё время и последние сутки, причины и постраничную историю. `/mod_pause` останавливает полномочия. `/mod_resume` означает, что текущая серия проверена, и начинает новый счётчик без автоматической отмены наказаний.

`/mod_undo ID` приостанавливает модератора и предлагает подтвердить отмену текущей серии. `/mod_undo ID all` предлагает отмену всей доступной истории, включая ранее проверенные серии. Бот сначала показывает конкретный объём; изменение истории после предварительного просмотра требует нового подтверждения. После отмены права остаются приостановленными.

## Защита от злоупотреблений

Модератор обязан указать причину предупреждения, отключения текста или голоса, блокировки, удаления сообщения, обработки жалобы и снятия своего наказания. Он не может наказывать SUPPORT или другого Moderator, снимать чужие санкции, сбрасывать аватары или закрывать лобби. Tester и Server owner не получают прав модерации и не имеют иммунитета от наказаний.

Каждое новое успешное действие попадает в журнал и уведомление главному администратору: сотрудник, цель, причина и время. После **10 действий без проверки** права приостанавливаются в той же транзакции. Это не скользящий таймер: выход из игры, повторный вход или снятие и возврат роли счётчик не обнуляют. Повторная доставка запроса с тем же nonce не считается новым действием. Параллельные запросы не обходят предел. SUPPORT под этот автоматический порог не попадает.

Отмена обрабатывает изменения в обратном порядке и проверяет текущее состояние записи. Она не затирает более позднее решение другого сотрудника, не возвращает уже удалённые по сроку хранения сообщения и не воскрешает удалённый аккаунт. Журнал сохраняется; отменить действия модератора можно и после удаления его аккаунта. Полномочия относятся к CZM, а не к админкам независимых игровых серверов.

## Обращения тестера

Настройки → Профиль → Сообщество → Отправить обращение. Только роль Tester открывает форму; тема и описание обязательны. Можно выбрать одну фотографию и один текстовый файл UTF-8.

- Фото выбирается системным окном, уменьшается до 1280 пикселей по длинной стороне и пересохраняется в JPEG без исходных метаданных. Сервер также проверяет тип, размер и число пикселей; итог до 1 МиБ.
- Текстовый файл — до 64 КиБ, UTF-8, без бинарного содержимого. Произвольные исполняемые файлы не принимаются.
- Приложению не требуется полный доступ к хранилищу. Читаются только выбранные файлы; смена аккаунта во время выбора не переносит вложение в другой аккаунт.
- Лимиты: 5 новых обращений в час, 30 в сутки; повторы одного запроса не создают дубликат.
- Текст, фото и файл уходят в приватный бот главному администратору. Доставка частей учитывается отдельно, чтобы повтор после ошибки не пересылал уже отправленные вложения.
- В основной базе обращение хранится до 90 дней или до удаления аккаунта. Служебные ID сообщений бота позволяют запросить удаление внешних копий. Если Telegram запрещает удаление, бот сообщает главному администратору о ручной очистке.

## Серверы проекта

Только Server owner управляет собственным списком: Настройки → Профиль → Сообщество → Серверы проекта либо кнопка управления в своей карточке. До пяти публичных числовых IP:порт; для IPv4 без порта используется 27015. Приватные и локальные адреса, доменные имена и произвольные URL не принимаются.

Название запрашивается у сервера; если он не отвечает, временно показывается адрес. Название обновляется при повторном добавлении адреса. Само добавление не подтверждает юридическое владение сервером: роль и проект выдаёт главный администратор.

Все игроки видят серверы в карточке владельца и могут подключаться нажатием. Список проекта не обходит личные или общие ограничения серверов. Глобально ограниченный сервер не показывается посетителям карточки; его владелец видит состояние в управлении. Снятие роли скрывает список, удаление аккаунта удаляет его.

## Совместимость и выпуск

Новые поля API добавлены без удаления прежних. Старые версии показывают только знакомые им значки; новые полномочия и защита проверяются сервером. Принятие правил редакции 3 требуется поддерживающим правила клиентам перед публичными изменениями.

Перед обновлением сервиса: CI, отдельные серверные тесты, резервная копия SQLite через backup API, установка точного SHA и проверка health/foreign keys. APK для установки — полный файл, собранный сервером; промежуточный core не устанавливается. Тестовый канал разработки и Google Play — отдельные выпуски.

Перед следующим отдельно разрешённым выпуском в Google Play нужно сверить Data safety с обращениями и вложениями, публичными данными профиля и обработкой в Telegram; актуализировать инструкции доступа к функции тестеров. Наличие модерации не подтверждает права на игровые ресурсы. Приёмка на телефоне остаётся обязательной: выбор и отправка вложений, смена аккаунта, карточки на разных размерах экрана, доступы двух обычных аккаунтов и приватность бота.
