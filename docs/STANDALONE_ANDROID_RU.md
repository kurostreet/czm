# Самостоятельная Android-сборка

## Устройство приложения

`MainActivity` подготавливает три встроенных архива: игровые файлы,
ресурсы движка и ресурсы клиента. Затем запускает внутреннюю
`su.xash.engine.XashActivity` через явный Intent в своём пакете.

Техническое имя класса движка сохранено для JNI. Отдельное приложение с пакетом
`su.xash.engine` не устанавливается и не требуется.

Сборка компилирует Xash3D и SDL через CMake/Waf, клиент и игровые библиотеки — через CMake.
Все библиотеки находятся в `lib/<ABI>/` одного APK. Поддерживаются arm64-v8a, armeabi-v7a и x86.

## Данные и первый запуск

- Архивы: `assets/bundled/{game-data,engine-resources,client-resources}.{zip,json}`.
- Подготовленные ресурсы: `files/bundled-data/<content-hash>/`.
- Настройки, сохранения и загрузки с сервера: `files/game/`.
- Движку передаются `XASH3D_RODIR` и `XASH3D_BASEDIR`, указывающие на эти разные папки.

Распаковка выполняется в рабочем потоке после проверки места и SHA-256.
Контролируются CRC, число файлов, распакованный размер и выход за целевую папку.
Незавершённые данные остаются в отдельной временной папке; движок их не получает.
Маркер готовности записывается после полного успешного завершения.
Повторный запуск не распаковывает архивы снова.
При смене ресурсов создаётся новая версия; пользовательская папка сохраняется.

Удаление приложения удаляет также его данные. После повторной установки полный APK
вновь готовит всё автоматически. Разрешение на доступ ко всем файлам телефона не нужно.

## Локальный полный APK из артефакта CI

В публичном репозитории хранятся код и исходники открытых зависимостей.
Предоставленный игровой архив подготавливается локально и не коммитится.

```sh
python3 scripts/prepare_game_bundle.py /path/to/game-cache.zip android/offline-assets
python3 scripts/assemble_offline_apk.py \
  --core /path/to/CounterZombieMobile-Core-test.apk \
  --assets android/offline-assets \
  --apksigner /path/to/tools/apksigner.jar \
  --keystore 3rdparty/xash3d-fwgs/android/debug.keystore \
  --output /path/to/CounterZombieMobile-AllInOne-test.apk
```

Скрипт добавляет архив в APK, выравнивает несжатые ресурсы, подписывает и проверяет результат.
Для локальной обычной Gradle-сборки используйте `CZM_GAME_ASSETS_DIR`, как в README.

Публичный debug.keystore upstream применяется только для тестов и обеспечивает одинаковую
подпись тестовых обновлений. Для публикации понадобится собственный ключ в закрытом хранилище.
Google Play — отдельная AAB-сборка (вариант `googlePlayRelease`, пакет `ru.kurostreet.counterzombiemobile`,
без обновлений из игры и без сжатия кода). Игровые данные идут в пакете ресурсов `gamedata` (install-time):
основной модуль Google Play ограничен 200 МБ. Порядок: Actions → «Counter Zombie Mobile for Google Play» →
Run workflow; CI отправляет неподписанный AAB на сервер, сервер кладёт игровые данные в `gamedata`,
подписывает ключом загрузки (`/var/lib/czm/signing/play-upload.p12`, пароль в `/etc/czm/env`, копия в
`/var/backups/czm-signing`) и выкладывает `https://counter-zombie.ru/dl/play/CounterZombieMobile-<версия>.aab`.
Этот файл владелец загружает в Play Console. Ключ приложения хранит Google (Play App Signing), поэтому
утерянный ключ загрузки заменяется через поддержку Play.

## Проверки

- Проверки Java-распаковщика на обычные файлы, traversal, превышение размера и неполные архивы.
- CI проверяет название, пакет, подпись и все 10 нативных библиотек для каждой из трёх ABI.
- CI проверяет SHA-256 встроенных ресурсов движка и клиента и название нативного меню.
- Полный APK дополнительно проверяется на телефоне без отдельно установленных Xash3D/CS16Client.
