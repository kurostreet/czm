# Сервис Counter Zombie Mobile

Живёт на VDS владельца (kontrafps.ru): API для игры, бот владельца в Telegram, мировой список серверов.
Один процесс uvicorn на `127.0.0.1:8200`, Caddy снаружи. База — SQLite в `/var/lib/czm`.

## Что делает

- **Профили и друзья:** `czm/social.py`, API `/api/v1/social/*`. Постоянный ID аккаунта, личный статус, друзья, односторонние подписчики/подписки и блокировки. `presence` раз в 30 секунд; онлайн истекает через 90 секунд, отозванный сеанс сразу теряет присутствие. Адрес текущего игрового сервера видят только сам игрок и взаимные друзья.
- **Личные сообщения:** `/social/dialog/<ID>` и `/social/dialogs`. Отправка только между взаимными друзьями; после удаления/блокировки история остаётся участникам для чтения. Повтор одной отправки с тем же `nonce` не создаёт дубликат. Есть непрочитанные, постраничная история и жалобы на конкретное ЛС через `/report` (`private_message`). Боевые рейтинги и неподтверждённая статистика не собираются.

- **Игроки:** `POST /api/v1/hello`. Игра шлёт свой секретный ключ (создаётся на телефоне), отпечаток устройства, ник, аватар, язык, версию.
  - В ответ: номер игрока, бан, номер последней новости, обновление.
  - Ключ и отпечаток хранятся только как хеш с «перцем» сервера.
- **Чат:** комнаты global, ru, en.
  - `GET /api/v1/chat/<комната>?after=N` — новые сообщения, удалённые владельцем, бан.
  - `POST /api/v1/chat/<комната>` — сообщение до 200 символов, не чаще раза в 3 секунды, повтор того же текста за минуту не проходит.
  - Мат заменяется на `***` (`czm/profanity.py`).
  - В комнате видны последние 100 сообщений, старше 7 дней удаляются.
- **Жалобы:** `POST /api/v1/report` на сообщение или аватар. Не больше 10 в час, одна жалоба на одно и то же раз в сутки.
  - Бот присылает владельцу текст (или аватар) и кнопки: бан на неделю / месяц / навсегда, удалить сообщение, не нарушение.
  - Бан — по игроку и по устройству. При бане за сообщение оно удаляется, за аватар — аватар сбрасывается.
- **Аватар игрока:** `POST /api/v1/avatar` (PNG/JPEG до 512 КБ) → `/avatars/<номер>.png`, 192 px. Без премодерации.
- **Новости:** `GET /api/v1/news?after=N`, пишутся командой бота `/news`.
- **Обновления выходят сами:**
  - GitHub Actions после каждой сборки шлёт core APK на `POST /api/v1/builds`. Пропускается только токен OIDC нашего workflow (репозиторий, ветка `feature/mobile-launcher`, `build.yml`), общих секретов нет.
  - `czm-assemble.service` (его будит `czm-assemble.path`, страхует таймер):
    - берёт игровые файлы из прошлой сборки на сервере;
    - подписывает публичным debug-ключом движка (`/var/lib/czm/signing`), сертификат обязан совпасть с прошлой сборкой;
    - сразу выпускает сборку игрокам.
  - Текст «что нового» берётся из `czm/whatsnew.txt` в репозитории. Если файл не менялся, пишется «Исправления и улучшения.».
  - В колокольчике появляется карточка обновления и новость с тем же текстом.
  - Владельцу в бот приходит «Вышло обновление» с кнопкой «Отменить выпуск», или сообщение, почему сборка не собралась.
  - `GET /api/v1/update?code=N`; APK лежит в `/var/lib/czm/apk` (последние 3), отдаётся с `/dl/` (с докачкой).
  - После подписи `czm/apkpatch.py` потоково готовит патчи от трёх доступных прошлых APK. Совпадающие сжатые ZIP-данные берутся из установленного APK; изменённые данные, заголовки и подпись идут в патче. Перед публикацией проверяется SHA-256 восстановленного APK. Патч без экономии не предлагается.
  - `hello` и `update` выбирают патч по установленному `code`: `patch_format=1`, `patch_url`, `patch_size`, `patch_sha256`, `base_sha256`. Обычные `url`, `size`, `sha256` полного APK сохраняются для старых клиентов и запасной загрузки.
  - Формат `.czmpatch`: `CZMPAT01`, длина JSON (uint32 big-endian), JSON-рецепт, один блок новых байтов. Операции `[0, offset, length]` копируют старый APK; `[1, offset, length]` — новые байты. Размеры и SHA-256 обоих APK находятся в рецепте. Патчи лежат рядом с APK, учтены в `release_patches`, удаляются вместе с вышедшим из хранения целевым выпуском.
  - Android проверяет базу (`ApplicationInfo.sourceDir`), скачанный патч и результат. Докачка проверяет HTTP Range. Ошибка патча включает полный APK, отмена останавливает загрузку. На телефоне APK не переподписывается; установку подтверждает игрок. Первое обновление со старого клиента остаётся полным.
- **Мировой список серверов:** раз в 5 минут из Steam Web API (нужен ключ `CZM_STEAM_KEY`).
  - Пишется в формате мастер-списка движка;
  - отдаётся по обычному HTTP: `http://kontrafps.ru/server-list/v1/servers/cstrike`.

## Бот

Тот же бот, что был у видео-проекта. Telegram с сервера закрыт, Bot API идёт через ретранслятор владельца.
Команды: `/news`, `/delnews`, `/release` (что у игроков; с текстом — поправить «что нового»), `/ban`, `/unban`, `/bans`, `/stats`, `/help`. Отвечает только владельцам.

## Установка и обновление

На сервере от root:

    curl -fsSL https://raw.githubusercontent.com/kurostreet/czm/<коммит>/server/czm/deploy/install.sh | bash -s <коммит>

- Код ставится в `/opt/czm/releases/<коммит>`, ссылка `/opt/czm/current`, окружение `/opt/czm/venv`.
- Настройки и секреты — `/etc/czm/env`: `CZM_BOT_TOKEN`, `CZM_BOT_API_URL`, `CZM_BOT_OWNER_IDS`, `CZM_PEPPER`, `CZM_STEAM_KEY`.
  - Первый раз бот берётся из `/etc/fva/env`, «перец» создаётся случайный.
- Письма с кодами (почта, вход, восстановление): сначала Resend (`CZM_RESEND_KEY`, отправитель `CZM_MAIL_FROM`,
  по умолчанию `Counter Zombie Mobile <noreply@counter-zombie.ru>`), запасной путь — SMTP (`CZM_SMTP_*`).
  Домен подтверждается в Resend записями DNS (DKIM `resend._domainkey`, MX и SPF поддомена `send`).
- Ключи вводит владелец сам, без показа на экране: `ssh -t market czm-set CZM_RESEND_KEY`;
  `czm-set check` показывает только PRESENT/MISSING.
  - Ключ Steam владелец вписывает сам.
- Служба `czm.service`, сайт Caddy — `deploy/czm.caddy` в `/etc/caddy/sites/`.

Сборку можно положить и вручную: APK кладётся на сервер, затем

    runuser -u czm -- bash -c 'set -a; . /etc/czm/env; cd /opt/czm/current; /opt/czm/venv/bin/python -m czm.cli add-release <apk> <версия> <код>'

и владелец выпускает её в боте `/release что нового`.
